# P3 内容创作验收

日期：2026-11-18。P3 核心后端范围完成：独立接口回归、四个新接口的试验台实测、10 组真实模型对照及文本核对通过。P7 的后端进入条件已满足，本轮未实施产品前端。

用户确认的顺序已落实：用户大纲原文直接留档；AI 仅按需丰富大纲且先生成候选；正文依据正式大纲生成；只在明确设定/视角冲突时针对性讨论并等待说明。P2/P2.1 前置代码已提交 `f54f409`，本轮 P3 在该基线上实现。

## 交付与边界

- 新增大纲留档、上下文预览、创作 SSE、来源与候选查询四个接口，已登记到试验台“内容创作”模块。当前 52 接口、11 模块。
- 支持章节生成、末尾续写、精确选区改写、AI 丰富大纲和讨论；资料包括作者指定的大纲、人物卡、作品要求、样文、历史原文及实际追加读取。
- 服务固定归属、路径、版本、修改范围和输出预算；只有审校 clear 后才允许提案，证据必须来自本轮原文。有待确认问题时，本轮不能自行解除。
- 模型仅创建 P2 候选。逐处采纳/拒绝、版本恢复、导出、外部改稿和引用冲突继续走已有资产服务；未采纳和停止不自动改正式稿。
- 小说请求使用独立业务提示和五个受限工具，普通聊天保留 P1 演示行为。创作记录通过 SDK 自定义元数据保存，候选来源随 P2 候选保存。

未实现全书自动召回、完整人物知情状态重建、自动偏好学习、自动多轮修订或产品编辑器。审校是模型对本轮资料的判断，不能保证找出所有语义问题。每轮完整资料快照最多 60000 字符；预算是字符约束，不能保证精确字数。

## 试验台实测

在隔离小说和真实浏览器中完成 32 项检查，涉及 16 个接口，包含所有四个新接口。模型协议替身决定工具步骤，其余使用生产后端、SDK、文件服务和 HTTP / SSE。

留档 → 保存人物 → 预览 → 生成 → 查询来源/候选 → 采纳 → 续写拒绝 → 再次续写采纳 → 历史恢复 → 导出闭环通过。设定冲突返回 needs_input；普通小说消息实际读取本书资料。顶部停止按钮留在创作页，结果为 aborted，之后可重新查询。

过期大纲、过期引用和越界路径分别返回预期 409/409/400。页面无运行异常，控制台只有这三个主动错误响应。截图 `output/playwright/p3-results.png`、`p3-stopped.png` 已查看；本机详细调用记录 `output/p3-browser-report.txt`。前端仅增加 P3 标记及复用停止交互，没有新增产品设计或布局。

## 真实模型对照

配置为 `krill-ai-codex / gpt-5.6-sol`，会话 thinkingLevel=off。使用本机 `.env`，没有将密钥写入记录。每组普通聊天与结构化方案使用同一套合成原文、目标和要求，分别新建独立会话；产物不读取或修改用户作品。

第一轮 10 组中 9 组流程通过，dialogue 失败：P1 的固定 A/B 提示和 read_fixture 演示资料与小说资源叠加，模型错误地把演示灯塔场景当作本章冲突。随后修复资源装配：业务请求接管默认提示/工具，P1 普通聊天保持原行为，并增加确定性回归断言。第二轮重新执行全部 10 组，全部流程通过；没有只重跑失败项或隐藏首轮失败。

完整可审核产物见 [结果 JSON](../evals/results/p3-20261118.json)。包含模型、提示及样本代码哈希、每组要求、普通聊天输出、结构化候选/审校、耗时、用量和阅读备注。原始隔离记录在 `output/p3-real-Rt8Yz7/report.json`，首轮在 `output/p3-real-KWKB4b/report.json`。

| 样本 | 普通聊天 | 结构化结果与逐份核对 |
| --- | --- | --- |
| 详细大纲场景 | 归还钥匙、船铃结尾成立 | 单个候选，人物限知与情节符合；开场说明误称续写，实际任务和候选正确 |
| 人物对白 | 师傅短句、学徒健谈；输出 A/B | 单个候选，无演示资料，最后先补船底 |
| 身体约束续写 | 右手拉铃，未让左腕负重 | 原文逐字保留，仅尾部增加，符合伤势 |
| 情绪选区改写 | 用动作替代情绪名称 | 非选区逐字保留，动作与雨停/炉火衔接 |
| 人物原则冲突 | 指出矛盾，等待选择 | needs_input，引用大纲与人物原文，无候选 |
| 视角知情冲突 | 指出无法确知他人想法 | needs_input，有正式原文证据，无候选 |
| 历史原文取证 | 引用粘贴资料中的完整铜扣句 | 实际 search/read，完整引文一致，仅讨论；后续物件来历仍需作者确定 |
| 样文与风格 | 短句、物件、留白 | 木梳入抽屉再修灯，无禁止套话，未复制样文情节 |
| 丰富大纲 | 保留离开结局，输出 A/B | 梗概体补动作衔接，原大纲未因生成而变化 |
| 重复句与 emoji | 给出替换建议 | 仅第二处改变，第一处及 emoji/前后句逐字不变 |

结论：这组样本验证了明确上下文、来源证据、候选保存和精确范围控制，并暴露和修复了演示资源污染。结构化方案的耗时和 token 明显更高，文本并非每项都比普通聊天更好。普通聊天沿用现有 P1 提示，存在 A/B 输出差异，这不是单变量实验。文本核对由 Codex 逐份阅读完成，不是作者盲评，也没有测量真实采纳率；不能据此宣称普遍文学质量提升。模型价格配置未提供真实单价，因此不报告金额。作者偏好与持续创作体验留到 P7/P8 验证。

## 联调与六条规则

接口示例、错误、SSE 和完整操作顺序见 [P3 接口](api/p3-writing.md)。`evals/writing-samples.ts` 保存 10 个固定合成样本；`node --env-file-if-exists=.env scripts/evaluate-writing.ts` 可重新创建隔离小说并运行对照。每次执行会调用真实模型。

| 规则 | 核对结果 |
| --- | --- |
| 不过度设计 | 复用 P2 候选和 SDK 元数据，未增加队列、任务引擎或独立上下文包 |
| 前后端完全解耦 | 前端只用公开协议；业务服务不依赖 Pi，SDK 只接收通用资源，server 装配 |
| 关键函数有注释 | 上下文、版本、审校、候选、资源生命周期及停止检查解释职责与原因 |
| 需求冲突先澄清 | 用户已确认原文大纲直接留档、AI 按需候选；没有自行改变主流程 |
| 替换旧接口先确认 | P1/P2/P2.1 公开接口保留，新建 P3 入口；小说业务与旧演示资源分开 |
| 前端边框与层级 | 沿用已有试验台，仅改标签和停止定位，无新增边框或层级样式 |

本机 4317 服务已在确认所有会话空闲后更新；4318 试验台代理正常，模型 configured=true，内置写作技能在小说范围可运行。后续进入 P7 时仍需单独执行交互、视觉和作者连续操作验收。
