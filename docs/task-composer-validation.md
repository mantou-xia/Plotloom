# TaskComposer 原版迁入验收

日期：2026-11-19

## 范围与实现

- 用户明确要求“就按照原版源码实现”，本轮以 LeiBox 原版样式和动效为准。
- `packages/ui/src/task-composer/original` 由官方 React 包的四个源码文件迁入；后续按用户确认将引擎中的形变外壳提取为通用 `MorphingPopover`，模型与权限菜单共同调用，其余三个文件未改写。`source.json` 分别记录上游 SHA-256 与引擎本地变更 SHA-256，目录内 `.gitattributes` 避免 Windows 换行转换破坏校验。
- `TaskComposer` 直接调用原版 React 入口，保留模型与权限胶囊形变、思考滑块光效/粒子、上下文浮层及附件布局。仅在宿主设置原站 16px / 1.5 字体基线，因为 Shadow DOM 仍会继承外部字号，调试台的 14px 字号会导致输入框高度相差 1px。
- 清理前一版自行实现的面板、组件契约和上传/压缩模拟；当前业务页面未调用前一版 TaskComposer。调试台改为展示原版实际支持的参数与六种样例。
- 按原版清单安装依赖。原版组件在调试台按需加载，不阻塞其他组件预览。

## 验证结果

- `pnpm.cmd typecheck`：通过。
- `pnpm.cmd ui:build`：通过。原版依赖较大，组件独立分包约 2.29 MB，gzip 约 683 kB；保留构建体积提示，未通过修改告警阈值隐藏。
- `pnpm.cmd test:ui`：20 项通过，包含组件目录覆盖和上游源码/已登记本地提取版本的完整性校验。
- 与 LeiBox 完整预览同宽对照：输入框宽 720px、高 132px，文本区高 60px、字体 14px / 24px，工具栏高 32px、间距 12px，双方一致；截图完成视觉核查。此为尺寸与视觉对照，不宣称所有运行环境像素完全相同。
- Chrome 实际验证：空白禁发、Shift+Enter 换行、输入法确认不发送；模型切换；思考档位点击、键盘切换及拖动松手回调；权限选择；上下文悬停显示与移出收起；本地文本附件读取、提交设置快照与提交后草稿清空；生成态更新保留草稿、停止回调不误发送；停止中与禁用状态；无模型提示与减少动态效果参数；窄屏面板不越界。
- 动效逐帧采样确认展开中的宽高连续变化，最终模型面板为 264px × 228px；使用原版弹簧参数与滑块渲染，未以普通淡入替代。
- 连续切换其他组件再返回三次，无残留组件实例，浏览器无页面异常。
- 验证脚本、结果及截图：`output/playwright/verify-original-composer.cjs`、`task-composer-original-report.json`、`compare-original-composer.cjs`、`task-composer-comparison.json`、`task-composer-original-*.png`（本地产物）。

## 当前边界

原版内部管理草稿和附件，提交后清空草稿。附件在浏览器内读取，未上传到服务器；上下文、技能及文件引用仍是原版未连接业务数据的状态。本次没有新增后端接口或将组件接入产品聊天页。当前 API 以 `packages/ui/README.md` 为准，后端差距仍参考 `task-composer-backend-adaptation.md`。

## 七条规则核对

1. 按明确要求直接迁入原版，没有继续增加自定义界面或业务能力。
2. 原版组件通过 options 与回调交互，无 Plotloom 后端内部依赖；内部 bridge 为本地状态，不连接服务。
3. 集成入口、字体基线原因、按需加载原因、调试台职责有注释；保留上游源码注释与署名。
4. 已就彩色边框冲突向用户说明，用户明确要求本组件按原版源码实现。
5. 根据用户对当前实现的纠正改为原版；检索确认前一版仅调试台调用，相关旧实现及旧示例已清理。
6. 本组件按用户本轮明确指令保留原版视觉细节；项目 `AGENTS.md` 全局规范未修改。
7. 组件与原版私有实现均维护于 `packages/ui`，调试台展示组件及真实公开参数，没有引入应用业务页面。

未新增或修改公开业务接口，接口试验台登记要求不适用。

形变外壳提取后的独立组件验证见 `morphing-popover-validation.md`；本次提取后已重新运行原输入框浏览器交互回归。
