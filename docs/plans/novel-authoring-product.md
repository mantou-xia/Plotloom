# 小说创作产品打磨清单

2026-11-21 建立，随讨论和开发持续更新。作者希望打开一本书后，在这本书的聊天里和 Agent 一起写作，随时翻阅正文、核对人物在当时的状态，并决定哪些改动进入正式稿。

原演示工作台支持登记已有文件夹、编辑 Markdown、按大纲生成章节、续写、选区改写、逐处采纳和版本恢复。这些能力作为实现基础。下列复选框记录新一阶段的产品目标，具体交互、工具契约和实施顺序可逐项讨论。现状见[小说工作台验收](../p7-novel-workbench-validation.md)。

## 首次使用场景：带着前三章旧稿写第四章

以下是本轮讨论确定的目标流程，供后续逐项开发和验收。

1. **建书并聊聊世界观。** 作者填写书名、绑定本机空文件夹。进入本书首次对话后，Agent 邀请作者讲讲开篇时主角所处的世界，后续随探索逐步补充。
2. **交旧稿。** 作者在一次对话中发来前三章旧稿，请 Agent 整理格式。Agent 按章节转成 Markdown，放入本书正文章节目录；作者在右侧工作区逐章打开，核对分章、段落和正文。此步以保留作者原文为准。
3. **建角色卡。** 作者用自己的话介绍人物。Agent 先归纳已有信息，再按五栏模板追问影响人物塑造的细节。例如作者已经说过“他表面随和”，可以接着问“什么情况下他会当面拒绝别人？”，避免重复询问外在性格。根据作者回答保存本阶段角色卡，供右侧查看与聊天引用。
4. **发起第四章写作。** 作者把第四章大纲直接写成聊天提示词，引用出场角色。每个角色默认使用最新阶段的角色卡。这里允许仅凭这条消息发起写作，现有按正式大纲文件生成的入口另有用途。
5. **交付整章。** 作者发起一次创作后，Agent 结合大纲、前文和角色卡写正文。第六阶段第一版在起草和润色时优先检查过度解释，再处理句式与描写。作者确认交稿后，新章保存并在右侧打开，已有章进入候选审阅。
6. **询问角色变化。** 交稿时，Agent 同时说明本章有没有需要更新的角色信息。有变化时，展示涉及的人物、原设定、建议变化和对应情节，并询问作者是否接受。接受后保存到相应阶段；拒绝则保留原卡。
7. **作者定稿并导出。** 作者可在右侧修改第四章，保存后，在聊天中请 Agent 导出 TXT。验收时特意手改一句对白，核对导出文件包含这句改动，段落和对白换行正确。作者取得纯文本后自行发布。

### 五栏角色卡的追问依据

建卡时沿用作者已经讲过的世界设定，只追问与人物有关的细节。

| 栏目 | 根据作者已给信息选择追问的细节 |
| --- | --- |
| 性格特点 | 分别记录表征、内在和描写。表征是别人看到的姿态，内在是真实的判断方式和情绪底色，描写说明两者如何在具体情境中呈现。 |
| 愿景 | 分别记录明示、潜意识和描写。明示是人物承认的目标，潜意识是在两难选择中推动行动、人物未必能说清的愿望。 |
| 社会背景 | 出身、经历、身份和关系，具体怎样影响他说话、待人、资源和风险选择？ |
| 外表特点 | 外貌、衣着、动作和物件如何帮助识别，并怎样与经历、背景或愿景关联？ |
| 特殊性 | 分别记录心理特质、口癖、禁忌和其他固定特征，只记录确有依据且会影响行为的内容。 |

参考图给出了五栏结构和填写深度。人物事实取自当前作者的设定，性格与愿景不得压缩成单一标签。内置模板已经同步细化；追问体验可用“只给一句人物简介”的对话验收。

## 从建书到开始对话

- [x] **首次对话引导（世界观）。** 邀请作者先讲已经想定的世界规则，按题材追问一个影响开篇的问题。例如作者提到武侠境界时，可以问：“主角刚入江湖时，觉得练到什么地步就算天下第一流？” 作者可以先讲眼前的几层，把更高境界留到后面构思，也可以先交旧稿。Agent 简要复述，经作者确认后将初始设定保存到本书根目录的 `世界观.md`。新开本书对话时沿用已确认的信息。
- [x] **随探索补充世界观。** 分别记录规则何时成立、主角何时得知。作者可以提前定下隐藏境界，也可以写到后面再补设定。若江湖规则在某章确实发生变化，保留变化前的规则及生效章节；若只是主角新发现既有规则，则记录揭示章节。交稿时，Agent 引用对应情节提出补充，由作者确认。

- [x] **新建小说。** 在「小说管理」和侧边栏小说列表提供同一个新建操作。作者填写书名、选择本机空文件夹，后端核对目录为空并初始化大纲、正文章节等目录。新书出现在两个入口，可以直接开始本书的创作对话。目录固定为“大纲”“正文章节”“角色卡”。
- [x] **带入已有作品。** 一次提交 UTF‑8 TXT 或 Markdown 旧稿，Agent 发起确认，后端按明确章标题导入并打开右侧预览。也可以手动放入已有 Markdown 章节。
- [x] **已有小说的处理。** 原登记仅用于测试。新书只绑定空文件夹，旧登记数据退出小说列表，磁盘上的原文件保留。

## 一章如何写出来

这里的**情节草稿**指创作产物，作者可以阅读和修改。它记录事件顺序、人物出场、谁在什么时机开口、想表达什么。编辑器刷新后找回的未保存文字是另一种状态，两者在界面上应有各自清楚的名称。

| 待开发或打磨的能力 | 期望结果与核对方式 |
| --- | --- |
| 大纲扩成情节草稿（后续设想） | 保留作者给出的关键事件与结局，把事件串成场景，标明对白发生的时机和意图。作者能在写具体台词前发现剧情遗漏。 |
| 分角色写对白（后续设想） | 不同角色依据各自已知事实、现场上下文和发言意图拟出台词。独立子 Agent 的调用方式和效果留待后续讨论。 |
| 写作时减少 AI 腔 | 按作者偏好减少惯用破折号和重复句式，适当增加具体描写。保留符合人物语气的短句、重复和停顿；以作者认可的样段判断效果。 |
| 成稿后检查并改写 AI 腔 | 找出读起来机械的实际句段，说明哪里重复或生硬，提供局部改稿，让作者能对照原文决定是否采用。 |
| 打磨细腻描写 | 将草稿中直白、青涩的表达改成符合场景的动作、感官或对白细节。例如人物迟疑时，尝试写他如何收回伸出的手。核对改写有没有改变原定情节或人物动机。 |
| 检查过度解释 | 找出动作、对白已经传达含义，叙述又替读者点破的句子。给出可删减的位置，核对删后既有留白，又能读懂因果。 |
| 随章节检查并更新角色卡 | 交稿时提出变化，作者接受后更新。旧阶段可以回看。作者修改证据段后，Agent 根据新稿重新判断并再次请求确认。其他段落的修改不影响原建议。 |
| 阅读章节与导出 TXT | 作者可在右侧读写章节，通过聊天导出该章最新保存的版本，保留自然段和对白换行。标题处理与整书导出范围待讨论。 |

## 阶段计划与开发顺序

以下八步是小说模块内部的建议开发顺序。各阶段共用同一本测试小说：前三章旧稿、两位出场人物和第四章大纲。这样，从旧稿里读到的一句对白，可以一路核对到角色引用、重写和最终导出。

| 顺序 | 本阶段交付与实现重点 | 可以进入下一阶段的验收场景 |
| --- | --- | --- |
| 1. 建书与进入本书聊天 | 初始化“大纲”“正文章节”“角色卡”，旧测试书无需迁移。后端实现空目录校验与初始化，两个新建入口复用同一操作，成功后进入本书会话。 | 分别从小说管理页和侧栏建书，核对磁盘目录、书名和聊天归属。选择非空目录时给出原因，其中原文件完好。 |
| 2. 右侧章节工作区 | 接入已有的文稿读取、编辑、保存、历史和冲突处理，补齐聊天旁的章节列表与 Markdown 预览。先用手动放入的章节验证，后续导稿可以直接在这里检查。 | 打开第三章、改一句对白、保存、预览，再回到同一本书的聊天。刷新后可以找回文稿与未保存草稿，磁盘外部改稿时能发现版本冲突。 |
| 3. 对话导入前三章 | 用作者实际持有的样本定首批格式和分章依据。聊天接收一次提交的旧稿，工具抽取正文、整理 Markdown 并写入本书章节目录。章界有歧义时向作者核对。 | 一次对话导入三章，右侧能按顺序打开三份文稿。用原稿逐章核对标题、正文和段落，再次提交同一旧稿时已有人工修改受到保护。 |
| 4. 五栏角色卡与阶段引用 | 先确定阶段含义及排序，再实现建卡、按阶段查询和引用。复用内置五栏模板与聊天追问能力；右侧查看人物，单书管理页回看历次阶段。 | 从一句人物简介开始，Agent 针对缺失信息追问并根据回答保存。用同一角色两个阶段核对历史可读、聊天默认引用最新阶段，并能查明该轮实际所用版本。 |
| 5. 从聊天大纲交付第四章 | 接受本轮消息中的大纲，读取前文、所引角色卡和本章适用的世界观。首次写新章直接保存，已有章节生成候选，前端在右侧打开结果。 | 发一条消息写出第四章并打开。设定第十章才揭示隐藏境界，回写第四章时，主角可观察到异常但说不出尚未知晓的境界名称。作者保存手改对白后再重写，只有采纳的差异写回；停止或重试均不能覆盖已有正文。 |
| 6. 正文文风打磨（第一版） | 在现有写作 Skill 中优先处理过度解释，其次调整机械句式和描写。覆盖聊天写整章和选区润色。 | 在相同输入下对照第五阶段和新版，作者逐段判断哪些解释该删、哪些信息和声音该留，核对改稿是否引入新动机。 |
| 7. 交稿后的角色卡与世界观变化 | 依据成稿分别提出人物变化、世界规则变化或主角的新发现，列出原文与适用章节。作者逐项决定，接受后可供后续写作引用。角色卡采纳时核对完整证据段。 | 用一章有变化、一章无变化验证提示。分别接受、拒绝建议，核对人物历史、世界规则及主角在揭示前后的知情范围。更改依据段落后按约定复核。 |
| 8. TXT 导出与作者连续试写 | 通过聊天导出指定章节最新保存的正文，处理 Markdown 排版并保留段落和对白换行。作者在正式界面从建书开始，连续完成一次第四章创作和导出。 | 打开导出的 TXT，对照右侧定稿，核对作者最后手改的那句对白和段落。记录试写中断点、返工原因及作者实际采纳的修改，作为下一轮打磨依据。 |

### 第四阶段实现记录（2026-11-22）

阶段按章节号排序，并允许填写作者备注。角色卡阶段写入 `角色卡/<角色名>/` 下的 Markdown 文件，正文采用细化五栏模板，其中性格特点拆为表征、内在和描写，愿景拆为明示、潜意识和描写，特殊性拆为心理特质、口癖、禁忌和其他。阶段元数据使用不可见标记记录章节号与备注。查询接口同时返回全部历史阶段和目标章节适用的最新阶段，聊天创作会自动把适用阶段作为 `character` 资料引用。Agent 可从作者确认的信息提取“黑化、失去双亲、获得神力”等变化关键词，通过确认卡调用 `save_character_card` 保存新阶段。小说工作台增加角色卡查看和创建入口。

独立接口测试覆盖两个阶段的章节筛选、历史可读、版本返回和未知路径错误。接口目录、试验台路由覆盖和类型检查已同步更新，详见[五栏角色卡接口](../api/character-cards.md)。

**依赖与排期。** 第一阶段确定作品归属和目录。第二阶段让作者能检查第三阶段的导入结果。第三、四阶段分别给写作提供前文和人物，所以第五阶段要等两者就绪。第六阶段沿用第五阶段的模型、材料和交付流程，便于判断改写规则的效果。第七阶段依赖角色阶段和成稿。单章 TXT 导出在第二阶段完成后即可独立开发，完整作者试写安排在最后。

**逐阶段交付。** 涉及业务接口时先定公开契约，实现后端并同步更新接口目录、独立接口测试和试验台，再接入产品界面。阶段记录保留试验台实际调用与作者入口的验收结果，涉及生成或写入时覆盖适用的停止、重试和版本冲突。角色对白、文风与连续创作体验另以真实样章和作者反馈验收。

### 世界观验收记录（2026-11-21）

- 新书聊天提示作者讲一条开篇规则，也可先交旧稿。口述内容通过聊天卡确认；若来自新生成的章节候选，先采纳章节，再在工作台独立审阅世界观建议。两者均复用已有版本和历史机制。[创作接口](../api/p3-writing.md)
- Edge 产品页验收覆盖新书提示、作者确认、文件落盘与重开聊天。试验台实际调用比较第四章与第十章的资料。独立 HTTP/SSE 回归覆盖拒绝、停止、跨聊天读取、证据核对、候选与正式章节的版本依赖，另检查读取与搜索工具不会返回该章尚未揭示的设定。
- 真实模型使用隔离的武侠样本。首轮模型把作者原话当作文件路径，工具拒绝保存。补齐口述引用规则后，同一要求触发正确的确认卡，保存后第四章世界观为空，第十章读到归潮境。此样本验证设定整理和分章引用；章节正文的文学效果留待连续试写。
- 界面复用原有聊天确认卡、输入框和工作台候选审阅。服务端独立处理证据、版本和章节筛选，公开契约及试验台示例同步更新。写作、资料、技能和试验台相关回归共 45 项通过；补充停止和工具检索断言后创作回归 13 项通过。类型检查及两端前端构建通过。

### 第二阶段验收记录（2026-11-21）

右侧面板按“正文／大纲”分栏展示文稿清单与稿纸。当前稿停笔或离开输入框后自动写入，预览基于当前内容，仅主动执行“定稿”才产生可回退记录。回退、自动保存和磁盘外部编辑都不会自动留档。两个文稿入口统一使用定稿记录，旧自动历史不再作为回退来源。

Agent 的面板工具逐项请求确认，包括浏览目录、打开、预览、提交改稿候选、留档及回退。修改已有文稿仍从候选审阅入口采纳，回退会校验作者确认前的文件版本，等待期间有外部改稿则提示冲突。实现复用项目控件和 Markdown 渲染、公开接口以及既有确认卡。[定稿接口](../api/p2-workspaces.md) · [Agent 工具](../api/p3-writing.md)

本次改版验收覆盖正文与大纲切换、自动保存、未保存草稿的即时预览、重复定稿去重、旧历史 ID 拒绝回退、定稿前后正文核对和窄屏。试验台实际调用了留档、查询和恢复接口。Edge 使用模型协议替身验证拒绝后面板仍收起，确认后打开指定大纲预览，以及已有创作和候选流程回归。

- 小说聊天的右侧工作区新增“正文章节”入口，只读取本书 \`正文章节/\` 下的 Markdown。大纲、角色卡和其他资料不会混入章节选择器，章节按目录和章号排序。
- 复用小说管理页的 Markdown 编辑、草稿、版本冲突、历史恢复和导出逻辑。聊天侧增加编辑与预览切换，预览显示当前草稿，切换章节和收起工作区后仍保留草稿。

- 类型检查、Web 构建和现有小说工作台回归通过。新增隔离浏览器脚本覆盖章节筛选、草稿刷新、预览、外部改稿冲突、历史恢复、窄屏和小说会话归属。测试中发现预览滚动容器需要固定高度，已补齐样式约束。

### 第一阶段验收记录（2026-11-21）

两个正式入口共用建书弹窗。作者输入书名和空目录后直接进入本书聊天初始页，首次发送消息时沿用现有机制创建归属该书的会话。接口沿用 `POST /api/workspaces`，后端串行检查目录归属和空目录条件，创建“大纲”“正文章节”“角色卡”。新书元数据位于服务数据目录的 `novels` 子目录，旧测试登记不迁移，原稿留在磁盘。接口及恢复路径见[工作区契约](../api/p2-workspaces.md)。

- 独立 HTTP 回归与试验台目录测试共 29 项通过。核实了含隐藏文件的非空目录返回 409、原文件与书单未变、新书目录准确、重复与嵌套绑定拒绝，以及备份恢复。补充建书目录说明断言后重跑目录测试，5 项通过。
- Edge 产品页连接隔离本机服务，从管理页及侧栏分别建书，核对刷新后的聊天归属及首次发送的会话响应。同轮小说工作台回归覆盖编辑、候选审阅、版本恢复、停止和导出。浏览器测试使用模型协议替身。
- Edge 接口试验台实际发送非空和空目录请求，分别显示 `WORKSPACE_NOT_EMPTY` 与成功结果；使用返回的工作区 ID 创建小说聊天成功。类型检查、产品和试验台构建通过。
- 按项目八条规则复核：复用现有布局、控件、聊天及接口契约；后端负责目录初始化，关键写入与回退有注释；旧登记处理已获确认。使用既有弹窗与浮动反馈，未增加边框样式。

### 第三阶段旧章节导入验收（2026-11-22）

- 三份作者样本均为 UTF‑8 TXT，每份一个章标题，标题与章节名可以相连，正文使用 CRLF，部分文件有前导或尾部空行。导入只整理标题及其分隔，正文逐字符保留。
- Edge 正式页面一次上传三份原样本。确认卡按第一至第三章列出标题，确认后右侧打开第一章，逐文件核对磁盘的正文与换行。接口试验台实测发送包含附件的消息、回答确认卡和查询章节列表。验收使用本机协议替身，未向模型供应商发送样本。
- 独立接口及目录回归 21 项通过，包含缺章标题、确认前不写入、跳过、停止、重复导入和已有手改冲突。类型检查通过。工具按会话绑定本轮附件，模型无法指定目标目录或替换正文。[导入接口](../api/p3-writing.md)

### 第五阶段整章写作验收（2026-11-22）

- 在小说聊天发送“写第四章：”或“重写第四章：”加本轮大纲，即可发起整章写作。后端固定目标文件、当章世界观、适用的角色卡阶段以及最近三章前文。优先引用大纲点名的角色，未点名时使用本章适用角色。
- 整章审校通过后展示正文并等待确认。作者确认后，新章保存到正文目录并打开右侧预览。已有章进入候选差异窗口，章节手改内容在作者逐处采纳前保留。成功新建后重试旧轮次返回版本冲突。
- Edge 正式聊天页验证了新章写入、自动预览、已有章差异和逐处采纳。接口试验台实际调用发送消息及回答确认卡，核对落盘结果。验证使用本机模型协议替身，整章文风与分角色对白留待后续实际试写。[聊天整章接口](../api/p3-writing.md)

### 第六阶段第一版实施计划（2026-11-22，已实现并实测，待作者评阅）

1. **先留对照稿。** 选同一本测试小说的第四章大纲与一组固定选区，通过第五阶段的小说整章和选区入口留存真实模型输出。固定模型设置、资料版本和作者指令，两版分别使用新会话，避免对话历史影响结果。
2. **在内置 `novel-writing/SKILL.md` 写入判断方法。** 限于创作和润色正文。读到动作、对白后的心理定性，或段尾的主题总结时，试删并连读上下文。保留推动后续行动的新信息、叙述者独有的声音和作者明确要写的心理活动。人物动机尚有歧义时保留歧义。用中文短例并列演示该删和该留的情形。
3. **再处理句式与描写。** 连读相邻句，优先改妨碍节奏的重复结构，保留有意的复沓。描写优先写准现场已有的人、动作和物件。删掉一句解释后，允许这一段直接结束。
4. **从实际入口验收。** 聊天整章在同一轮起草和自检后走 `deliver_chapter`。选区润色走现有 `rewrite` 和候选审阅，仅修改选中范围。作者只问哪里多余时，在聊天中指出原句。设定和视角冲突沿用既有审校。
5. **用样章判断效果。** 固定选区覆盖对白后的重复点题、必须保留的因果、刻意留白、机械句式和作者已满意的描写。在相同条件下用新版再跑一次，打乱版本顺序，请作者标出保留、退回或两版相当的句段及原因。单独记录误删因果、补写动机或破坏人物声音的位置，修订规则后用留出的段落复核。阶段验收以作者实际评阅为准。

### 第六阶段第四章实测（2026-11-22）

- **测试材料。** 采用作者给出的六点大纲，以《勋鹿监护人》前三章作为前文。旧 Skill、两次中间修订和交付版分别在隔离小说、新会话中运行，模型均为 `gpt-5.6-sol`，思考关闭。桌面第四章样本仅在生成后用于比较。另取原作品已有第四章的“夫妻分钱”和“同父异母”两段，通过独立副本测试选区。
- **整章。** 交付版完成六个情节点。旧版在“三年前”之后再问谁来争监护权，交付版收在鹿晗握着听筒说不出话，更接近样本。旧版正文 4113 字符，交付版 3746，作者样本 2132（含标点，去标题及空白）。思母段仍重复写失落，夫妻谈完钱后仍出现“明码标价”的作者点评。泡面先写从厨房翻出，随后才补说是楼下买的，衔接也较样本生硬。
- **选区。** 初次实测把道德点评换了说法。把整句删除、跨段连读写入 Skill 后，两次实测均删去了钱属于失母孩子的点评，仍保留了鹿晗并不知情的过渡句。留出段保留了家庭关系的疑问与前世线索，也沿用了原稿“钝刀”的比喻。两个交付版候选均验证选区外字符完全一致，正式稿版本保持原值。
- **验证。** 整章经真实聊天入口执行审校、确认和交稿，选区经创作接口生成候选。相关技能、创作与试验台回归共 37 项通过。此次变更集中在内置写作 Skill 的正文方法，沿用现有公开接口和审批。实测只覆盖一本小说的第四章，作者对各段的取舍尚待记录。

### 第七阶段角色卡变化验收（2026-11-22）

新章交稿确认后，Agent 按人物展示旧卡、适用章节、证据段和建议新卡。作者接受才新增阶段，后续写作按章号引用。已有章节重写须先完成正文审阅并采纳，再在原聊天复核角色变化。角色卡读写契约与试验台示例见[角色卡接口](../api/character-cards.md)。

- 通过公开 HTTP/SSE，以模型协议替身交付章节。分别接受、拒绝和停止，核对磁盘上的历史卡。只追加其他段落仍可接受。保留引句但在同段补写“原来那是一场梦。”时，旧确认失效，重新确认后只保存“梦醒”阶段。等待时作者新建角色阶段会阻止旧建议写入。重写采纳后重启服务，在同一聊天继续复核成功。
- 在 Edge 接口试验台实际发送角色卡创建、读取、列表和小说聊天请求。缺少证据正文时创建返回 400，保存示例正文后返回 201。证据变更用例有一次交稿确认和两次角色确认，历史只增加一张。停止用例和无变化用例均未新增角色卡。模型判断由固定样本驱动。
- 使用原有聊天确认卡及候选审阅控件。后端负责版本、段落和工作区归属检查，仍由公开协议提供资料。该项只记录角色卡变化的验收。

### 交稿后缺卡提醒验收

新章保存后，Agent 结合实际出场、关系和承诺判断是否值得提醒。重写候选可先发起核对，工具在正文审阅完成后继续；全部拒绝时不提示。已有当章适用卡会跳过，只有后期卡则提醒补早期阶段。使用稳定称呼建卡时，会提示核对可能的已有身份。

通过真实 HTTP/SSE 和模型协议替身验证了跳过后重启、改引同段另一句、后来有新情节、补早期阶段、等待时停止、起草后另行确认保存，以及重写采纳和全拒绝。Edge 接口试验台实际发送小说聊天请求并核对角色历史：同意起草并确认保存新增一张卡，跳过和停止均为零张。人物重要性由模型判断，这组测试验证作者的选择如何影响正式角色卡。详见[角色卡接口说明](../api/character-cards.md)。

## 技术拆分与推进

建议将大纲扩写、对白、描写和审稿方法放入写作 skill；同一种读章节、查卡片或提交候选的操作可被多个 skill 复用。建目录、转换旧稿、取指定阶段的角色资料、保存候选和导出 TXT 需要后端提供确定的结果。后续按聊天或页面的实际调用需要决定哪些能力公开给 Agent 作为工具。前端沿用公开接口。后端在保存新章时核对目标是否已存在，对已有正文沿用版本核对与候选采纳流程。已有设计见[小说技能与工具职责](novel-skills-architecture.md)。

交稿验收用同一章连续操作两次。第一次写第四章，核对右侧打开的终稿与章节目录中的文件一致。作者手改一句对白并保存，再要求重写，核对现稿仍保留这句对白，只有采纳的改动才写回正文。角色卡更新由作者单独决定。

后续每确定一项，就在对应条目补上已确认的交互、需要的后端能力和验收场景。工具操作按项目既有接口与试验台要求验证；写作效果记录作者对同一段原稿和候选的取舍及原因。完成后勾选条目并附验收记录。
