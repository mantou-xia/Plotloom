# P1.1 通用 Agent 配置与管理

日期：2026-11-17。范围经本轮对话确认：模型能力、默认配置、会话配置、会话命名、上下文管理、累计用量、只读工具信息，以及模型返回的思考文本。

## 实施顺序

1. 扩展公开契约：在现有模型、默认配置、会话和消息响应中增加能力、名称及思考字段；增加会话配置、名称、上下文、压缩/取消、统计、工具查询接口。
2. 复用 Pi 1.5.2：模型/档位保存到原 SDK 会话；所有写操作与生成互斥；手动压缩由 SDK 执行并可取消。读取和生成分开校验凭据。
3. 思考只映射 SDK 实际返回的文本。流使用独立 thinking_delta，历史使用 thinking 内容块；排除签名、加密数据和供应商元信息。不承诺模型一定返回可见思考。
4. 接口试验台全量登记、字段检查、模型/档位选择和独立思考展示；继承原有样式，不新增页面框架。
5. HTTP 验证保存/重启、会话隔离、并发冲突、压缩/取消/失败、思考流与历史、能力限制及错误脱敏。浏览器实际调用全部新增接口；真实模型验证思考及配置，记录可见性限制。
6. 更新接口和验收文档，回归 P1 并检查六条开发规则。

## 约束与原因

- 在现有接口上增加字段及新入口，保留原 8 个操作的用途。默认配置只影响新会话；已有会话通过自己的配置接口调整。
- 不支持的显式思考档位返回可读错误；只切换模型时由 SDK 按能力调整并返回有效档位，避免页面宣称未生效的选项。
- 会话 status 仍为 idle/running，增加 activity 区分生成、配置和手动压缩。生成中不可改配置，防止结果与当前模型标识混淆。
- 上下文占用采用 SDK 的估算/未知口径；累计用量仅统计已保存的已知用量，不把估算或占位价格当账单。
- 暂不扩展对话分支、追加指令队列、工具动态启停和凭据管理。

## 实施结果

以上六步已完成，详见 [P1.1 验收记录](../p1.1-validation.md)。当前真实模型 low 档未返回可见思考；协议映射、保存和页面分区均已用确定性数据验证，未虚构真实思考结果。
