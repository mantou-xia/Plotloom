# P2 Markdown 工作区实施计划

2026-11-18。用户确认旧 JSON 资产无用、不需兼容；先核心后端闭环，再前端，再补充额外后端能力。本计划执行 P2 资产与候选基础，不提前开发 P7 产品页面；P2.1 技能管理/聊天关联和 P3 模型写作接入分别验收。

执行结果：P2 已完成；全量 40/40、类型检查、构建及 17 个接口的试验台实测通过。Windows 提交占用和进程中断验证见 [验收记录](../p2-validation.md)。以下保留实施前计划与关键决策。

## 1. 顺序与完成条件

1. 统一 architecture、roadmap、project-structure、README 和业务方案；清理旧草稿，恢复类型检查。
2. 公开契约、工作区登记、Markdown 列表/读取/手工保存、历史与恢复。
3. 候选差异、逐处采纳/拒绝、乱序处理、重复提交与外部改稿冲突。
4. 指定原文搜索、Markdown 导出、包含版本和候选的文件备份。
5. 每个新增接口登记到 catalog，试验台可填写路径参数并执行；独立 HTTP 测试、目录覆盖、浏览器实测与类型检查通过后记录验收。

P2 完成不等于写作闭环完成。P2.1 处理技能库/外部目录导入及小说聊天归属；P3 在此基础上注册读取与候选工具，完成内置写作 skill、指定章节引用、冲突讨论、章节与选区生成、停止及真实模型效果验收，再进入 P7。

## 2. 数据与接口决策

- 每本小说登记一个已经存在的绝对目录；用户创建目录后通过接口打开。拒绝重复或相互嵌套工作区，避免同一文件同时属于两本小说。
- 不强制“角色/章节/大纲”等目录名；列出目录内的 `.md` 文件，相对路径是文件身份。用户可按业务建议组织，重命名视为旧路径消失、新路径出现。
- UTF-8 Markdown 是正式资料；不再保存编辑器 JSON 或整书 JSON 正文。路径统一 `/`，禁止绝对路径、`..`、符号链接/目录联接和 Windows 别名路径绕过。
- 元数据采用服务数据目录下的 JSON（登记、版本清单、候选状态），正文快照独立保存为 `.md`。这是内部登记格式，不是旧 JSON 资产兼容层，也不是当前正文的第二份权威来源。Pi 会话继续由 JSONL 持有。
- 文档版本为内容 SHA-256，文件不存在为 `null`；历史记录另有唯一 ID，因此恢复旧内容仍新增历史记录。只记录实际观察到的内容，不宣称捕获外部每次保存。
- 选区为 UTF-16 半开区间 `[start,end)`，附 `text` 精确核对；不得切开代理对。候选请求提供选区替换内容，后端只在该范围内计算差异。
- 后端按行计算相邻增删为一处差异；分隔的未变行分开处理。不依赖模型给出的行号或文字总结。每处记录基础原文范围、before/after、独立状态和提交版本。
- 采纳时重建“基础稿 + 已采纳各处”作为预期当前稿，再应用选中修改；因此乱序采纳与前方长度变化不会使后方错位。重复采纳直接返回既有结果。拒绝不检查磁盘也不写正式稿。
- 候选记录实际参考文档版本；采纳遇到参考资料变化返回依赖冲突，保留候选，要求重新核对后创建新候选。首版不提供强制覆盖或自动合并。

## 3. 文件提交与失败处理

当前目标是 Windows 本机。先验证 FileStream 共享模式在独立进程读写、替换时的行为；比较基础字节和写入必须位于同一持有写入排他权的句柄生命周期内。不能把应用内串行队列当作外部进程锁。

提交前持久保存原稿/目标快照与待提交记录；写入子进程 ID 先落盘，再向其发送指令，成功后更新版本和候选状态。下次打开若发现待提交记录，先确认旧写者已退出；仍在运行则返回 FILE_BUSY。之后磁盘等于目标则补齐元数据；等于原稿则取消未生效提交；其他内容返回明确未决提交冲突，保留全部快照，允许用户查看并显式按当前磁盘结束未决记录。不得猜测并覆盖外部修改。此记录仅保护文件与业务状态，不是通用工作流引擎。

备份输出真实文件目录，包含 Markdown、历史、候选与登记；不复制凭据。P2 备份只包含本阶段资产，Pi 会话全量备份仍由 P8 统一验证。导出返回选定文件或历史版本的原始 Markdown，不转义成另一种内容。

## 4. 验收场景

- 两工作区同名文件隔离；越界路径、联接和重叠登记被拒绝。
- 读取外部改稿、过期保存/恢复冲突；UTF-8/BOM/CRLF 和重复句子保持准确。
- 新建候选不产生正式文件；新建期间同路径被占用时冲突。
- 至少三处差异乱序及部分采纳，重复采纳不重复记录；重启后继续处理。
- 选区外文字不变；中文和 emoji 偏移正确；大纲/人物资料变化触发依赖冲突。
- 外部进程持有写句柄时提交失败且原稿不被覆盖；提交句柄持有期间外部写入与替换失败。
- 写入前后进程中断的待提交记录可识别；未决情况不自动覆盖。
- 历史恢复形成新记录；导出内容相同；备份中的 Markdown 和状态可读取。
- 所有新增路由在独立接口测试与试验台实际调用，错误用例有记录；P1/P1.1 回归通过。
