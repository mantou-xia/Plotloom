# P3 内容创作实施计划

2026-11-18。前置 P2/P2.1 已提交 f54f409。用户确认：用户提供的大纲原文直接保存为正式 Markdown；AI 仅在用户需要时辅助丰富大纲，AI 改动先生成候选，经采纳后更新；正文依据确定的大纲生成候选。不固定安排大纲讨论，具体设定冲突仍需说明并等待用户。

## 实施顺序

1. 同步业务说明，定义创作请求、上下文来源、审校问题及结果的公开契约。保留原通用会话与 P2 资产接口。
2. 大纲留档复用手工保存业务；编译目标、选区及邻近文本、大纲、人物/作品要求/样文/历史引用，校验版本与归属。
3. 接入小说读取、搜索、审校与候选工具。请求开始固定资料；新增读取保存来源。模型只可提交候选，结构化创作限制目标与选区，续写仅在末尾追加。
4. 创作记录通过 SDK 自定义元数据保存，候选归属随候选原子保存；前端可查询来源、审校和候选。复用 SDK 生成/停止/重试/压缩，不建设运行时或队列。
5. 注册新增接口及修改字段到试验台，补独立 HTTP 测试和目录覆盖，进行实际浏览器正常/错误/停止验证与全量回归。
6. 准备至少 10 个合成样本及普通聊天对照评测入口，配置真实模型后记录效果、耗时和用量；没有凭据时明确保持真实验收待完成，不将 P3 或 P7 进入条件标为完成。

## 关键决策及原因

- 创作任务区分章节生成、续写、选区改写、大纲丰富与讨论，避免模型自行猜测操作范围。章节生成读取已保存的大纲；大纲丰富只修改大纲目标。
- 原文大纲保存是用户动作，不经过模型重写。AI 产物全部走现有候选服务，保留逐处采纳和引用冲突规则。
- 资料按相对路径与版本引用，用户可选择具体片段；不依赖中文目录名或自动全书检索。资料超出当前输入预算明确拒绝，不静默截断。
- 候选输出设字符预算；模型的最大 token 仍服从模型配置。不承诺字数精确或语义检查完备。
- 最小审校由模型提交问题及原文证据；证据必须来自本轮资料。存在待确认问题时本轮不能提交候选；普通无冲突请求不需要额外人工审批。
- 通用 Agent 只新增请求资源与元数据接入点；小说业务不进入 Pi 包，工具薄适配在服务装配侧。普通聊天保持原行为，小说聊天按固定归属获得受限资料能力。
- 已完成候选即使之后停止也保留可查询，但未采纳内容不会写入正式稿。服务中断后只展示已保存记录，不自动续跑。

## 验收重点

- 大纲逐字留档、版本冲突与重启；AI 丰富未采纳不改大纲，正文只读取正式大纲。
- 章节、末尾续写、精确选区、重复句/emoji，非选区不变；模型不能扩大结构化请求目标。
- 人物/历史/样文来源可查，跨书隔离，路径越界拒绝；引用更新不会静默采用新版本。
- 审校证据校验、缺失资料与具体冲突等待；候选只有清晰审校后才能提交。
- 断流、停止、重启、外部改稿、引用冲突、逐处采纳/拒绝/恢复与导出全链路。
- 全部公开接口可从试验台实际触发，P1/P2/P2.1 回归通过；真实样本结果与确定性验证分开记录。
