# P2.1 技能管理与小说聊天关联实施计划

2026-11-18。用户已允许继续 P2.1，并明确确认：聊天默认跟随工作区，聊天单独设置后覆盖工作区，也能恢复跟随；修改从下一条消息生效。

## 范围与顺序

1. 建立公开技能/启用/聊天归属契约及实际文件仓储；支持技能列表、详情、自定义创建、文本资源编辑、完整目录导入、复制和删除。
2. 工作区技能默认值与聊天覆盖；通过小说入口创建聊天，查询小说聊天与全部最近聊天。原通用会话接口继续可用，消息只由 Pi JSONL 持有。
3. 请求开始时固定技能与资源内容；向模型提供技能摘要，按需用受限 read_skill 工具读取，支持显式选择技能。内置小说技能在小说默认配置中出现；P3 未提供的小说工具应报告缺失，不能伪装可运行。
4. 每个公开接口注册试验台；独立 HTTP 测试、模型协议替身的真实工具循环、浏览器实际调用、类型检查、构建和 P1/P2 回归。
5. 记录验收及限制，更新路线图；本轮不实现 P3 小说模型工具或产品前端。

## 关键决策及原因

- 技能安装到应用数据目录；导入复制完整普通文件树，不原地依赖外部目录。保留二进制 assets 与 scripts，但不执行代码。只允许受限技能文本资源读取，不能访问任意本机路径。
- SKILL.md 使用 YAML frontmatter，校验 name、description、compatibility、allowed-tools 等声明。依赖展示区分缺少已声明工具、待人工核对的环境说明和不执行脚本；不声称理解所有自然语言依赖。
- 每次资源修改写入新的版本目录并原子更新清单；请求从选定版本读取到内存后固定，运行中的请求不受修改/删除影响。正式技能源码是实际文件，没有运行时插件系统。
- 内置资源只读，可复制为自定义版本后修改。外部导入可编辑应用内副本，不改原目录；同名不静默覆盖，冲突时要求使用其他名称。
- 工作区未设置时使用内置 novel-writing；显式空列表表示关闭全部默认技能。聊天 skillIds:null 表示跟随，数组表示完整覆盖，空数组关闭。普通聊天跟随时默认无技能。
- 小说归属在创建时保存为 SDK 自定义元数据，此后不随导航变化，不提供聊天迁移接口。聊天技能设置也由 SDK 自定义条目保存，避免复制完整聊天或跨文件写入聊天归属。
- Pi 适配接收通用的每请求技能资源提供器，不导入小说服务或存储。当前 SDK 摘要发现对默认 read/bash 名称有要求，本项目显式注入摘要并提供 read_skill，避免开放通用文件或终端工具。
- 显式使用已启用技能采用消息字段 skillIds（只影响该次调用是否立即加载说明，不改变启用配置）；未知、停用或依赖不满足时返回公开错误。普通自动选择只包含可运行技能，查询接口显示所有配置及不可用原因。
- 公共会话配置、名称、停止与流式协议继续复用；技能设置可在生成中更新，只改变后续请求，不改变当前工具集合。

## 验收

- 导入完整目录后 references/assets 可读、二进制可取回，脚本不执行；坏格式、链接、越界和同名冲突明确拒绝。
- 创建/编辑/复制/删除、内置只读、过期编辑保护；源目录变更不影响已导入副本。
- 不同小说与普通聊天隔离；最近列表带归属；重启保留空聊天、设置与历史。
- 默认跟随、聊天覆盖、恢复跟随、显式空列表生效；进行中的请求读取旧快照，下一请求使用新版本。
- 按需读取和显式加载均通过公开消息接口进入模型；未启用技能不能读取，停用不抹去历史，但不能获得当前资源访问能力。
- 缺失工具/环境诊断不冒充已运行，停止仍有效，P1/P2 回归与试验台覆盖通过。

## 实施结果

2026-11-18 已完成以上范围：15 个新增接口及消息 skillIds 字段，类型检查和构建通过，全量 48/48 回归通过，试验台覆盖全部新增接口和技能读取/停止。详见 [公开接口](../api/p2.1-skills.md) 与 [验收](../p2.1-validation.md)。

浏览器验证发现 Windows 新目录 rename 偶发 EPERM；发布改为先仅创建版本文件、校验完整内容，再原子更新清单，避免目录重命名，也不覆盖已发布文件。40 次连续安装与版本复用及全量回归通过。

P2.1 验收时真实模型凭据未就绪，模型协议替身仅证明接入和工具循环。当时内置写作方法缺少 P3 小说工具，明确不可运行。随后 P3 已补齐工具并完成 10 组真实对照，见 [P3 验收](../p3-validation.md)；产品前端仍未开始。
