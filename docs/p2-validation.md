# P2 Markdown 资产与候选基础验收

日期：2026-11-18。结论：本阶段已完成并通过验收；核心模型写作闭环仍需 P2.1 技能/聊天关联和 P3 写作接入。用户已确认旧 JSON 正文资产无用、不兼容，相关草稿已清理并按 Markdown 重新实现。

依据：[实施计划](plans/p2-implementation.md)、[公开接口](api/p2-workspaces.md)、[路线图](roadmap.md)。本轮无 `.cursor/rules/*.mdc`，未找到 `space` 约定上下文；按根 AGENTS.md 与已确认业务范围实施。

## 1. 交付范围

已实现工作区登记、真实 Markdown 列表/读取/保存、历史与恢复、候选/按行差异/逐处采纳与拒绝、选区修改、参考版本冲突、原文搜索、Markdown 导出、资产备份及未决提交核对。

新增 17 个公开 JSON 接口，登记到 catalog 的三个资产模块。试验台现在共 33 个接口、7 个模块；前端只通过 HTTP 调用。通用会话和 SDK 行为保持原协议，未增加模型正式稿写入工具，也未开发 P7 产品编辑器。

独立服务子进程通过公开 HTTP 完成以下场景，文件占用和中断由测试夹具制造，不依赖试验台内部代码：

- 两个工作区同名文件隔离、跨工作区资源不可用，重启后资料可读。
- 手工新建/保存、并发保存、过期版本、外部编辑与不存在的文件状态。
- 三处差异乱序及顺序采纳、前方长度变化、混合拒绝、重复决定、部分处理后重启继续。
- 精确选区、重复句子、中文/emoji、BOM/CRLF；非选区文字保持不变。
- 新文件候选不落正式稿、被外部同名文件占位时拒绝采纳、拒绝不改稿。
- 引用资料变化及部分采纳后外部改稿返回冲突。
- 历史恢复创建新记录、旧内容可导出、指定章节原文搜索。
- 外部进程持有写句柄时提交返回占用错误，原稿保持完整。
- 越界、联接、路径别名、错误编码及协议字段被拒绝。
- 注入写入前/写入后/另有改稿三类中断状态，验证撤销意图、补齐元数据、保留未决冲突及显式保留现稿。
- 真实强制结束父服务进程；重开时不会越过仍在运行的写入子进程；写者退出后按磁盘和意图核对。
- 按备份 README 的步骤恢复到新的服务数据目录和 Markdown 目录，文稿、历史与候选状态一致。

P1/P1.1 会话、SSE、停止、重试、压缩与配置回归同时通过。运行中出现 Fastify 已有弃用提示，不影响测试结果；未将升级框架纳入本次改动。

## 3. 试验台实际调用

使用 Playwright CLI 操作真实页面、发送 HTTP 请求；测试后端使用独立的临时工作区和数据目录，不使用用户作品。更新后的后端完成 25 次请求，覆盖全部 17 个新增接口。成功响应在页面均显示“检查通过”；以下主动错误请求符合预期：

| 场景 | 预期及实测 |
| --- | --- |
| 重复登记目录 | 409 WORKSPACE_OVERLAP |
| 旧基础版本覆盖现稿 | 409 REVISION_CONFLICT |
| `../越界.md` | 400 INVALID_REQUEST |

页面完成登记→保存→三处候选→采纳第 1/3 处、拒绝第 2 处→重复采纳→读回核对→历史恢复→搜索→导出→备份→恢复状态查询。工作区、候选和差异 ID 自动带入后可编辑，路径参数布局已检查。

浏览器没有观察到运行时 JavaScript 异常，控制台仅记录上述三次主动触发的错误 HTTP 响应。截图与执行脚本保存在本机忽略目录 `output/playwright/p2-proposal.png`、`output/playwright/p2-browser-run.js`；它们是本轮证据，不是仓库交付依赖。P2 无流式生成或停止操作；P1/P1.1 停止回归已通过，P3 再验证模型生成候选的停止行为。

## 4. Windows 文件提交补充验证

使用实际 `commit-markdown.ps1` 的临时副本，仅在打开句柄后增加暂停点；由另一 Node 进程尝试修改同一临时文稿。该探针验证操作系统共享行为，未修改生产提交脚本。

| 持有提交句柄期间的外部操作 | 结果 |
| --- | --- |
| 写入 | EBUSY，失败 |
| 重命名原文件 | EBUSY，失败 |
| 用另一文件替换原文件 | EPERM，失败 |
| 删除 | EBUSY，失败 |
| 读取原稿 | 成功且内容不变 |
| 释放暂停并完成提交 | 成功，中文/emoji/CRLF 内容正确 |

本机探针和报告：`output/p2-lock-probe.mjs`、`output/p2-lock-report.json`。验证支持“同一排他写句柄内比较与提交”，不将进程内队列当作外部文件锁。

## 5. 已知边界

- 文件提交当前仅支持 Windows；未验证每个外部编辑器的提示行为，不宣称跨平台写入已完成。
- 不保证整机断电事务或多文件同时点快照。进程中断时以已保存快照、提交意图和实际磁盘核对；不确定内容不自动重写。
- 版本只记录应用观察或提交的内容；没有捕获外部每次保存的文件监听历史。
- 备份范围为正式 Markdown、候选与版本；不含 Pi 聊天、凭据和非 Markdown 附件。备份期间须暂停外部编辑，完整应用恢复在 P8 验证。
- 搜索为字面子串，导出为原始 Markdown；自动事实、向量检索、去格式 TXT 和高级风格能力后置。
- 本轮没有调用真实模型，不能据此宣称章节质量、人物冲突讨论或写作 skill 已验证。P2.1/P3 仍需独立交付，之后才进入 P7。

## 6. 六条铁律与接口交付核对

| 要求 | 结果与依据 |
| --- | --- |
| 不过度设计 | 仅实现当前资产和候选用例；普通文件存储，无数据库迁移框架、队列或工作流引擎 |
| 前后端完全解耦 | 试验台只依赖 contracts 和 HTTP；application/domain/storage 不依赖页面或 Pi，独立 HTTP 测试通过 |
| 关键逻辑有注释 | 选区/差异、逐处采纳、路径边界、排他提交、写者登记与恢复注明职责和原因 |
| 冲突先澄清 | 主文档冲突已先暂停并取得“核心后端→前端→额外能力”的明确答复，实施前形成计划 |
| 替换前确认 | 用户已明确旧 JSON 资产无用，清理旧草稿后重建，无兼容分支 |
| 边框与层级 | 试验台沿用背景与间距布局，新路径输入未引入盒子嵌套、彩色边框或边框叠加阴影 |
| 接口登记与试验台 | 17 个新接口完整登记，33 个路由全目录覆盖，浏览器实际调用通过 |
| 独立接口与验收 | 自动化、实际文件冲突、重启与备份恢复均记录；未把未实现的模型流程标为完成 |
