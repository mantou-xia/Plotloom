# 自动压缩开关验收

日期：2026-11-19。范围：当前会话自动压缩设置的公开接口、持久化、Pi 实际行为与接口试验台。产品聊天控件接线不在本阶段内。

## 执行计划及实现

1. 核查 Pi 1.5.2：复用 `setAutoCompactionEnabled()`，不新增压缩算法或执行循环。
2. 扩展现有会话配置契约：`PUT /api/sessions/:id/config` 接受可选布尔值 `autoCompaction`；GET/PUT 配置响应返回该字段，context 返回值保持一致。
3. 使用 SDK custom entry 保存当前会话设置，创建 SDK SettingsManager 时恢复。原因：原先每次打开或重建资源都会创建开启自动压缩的内存设置，仅调用 setter 无法跨重建保留。
4. 保持现有配置互斥：生成、配置或手动压缩中返回 409；不在运行中改变本轮行为。单独切换开关不调用模型、不要求凭据；同时修改模型/档位时先完成验证。
5. 更新目录、独立接口测试与试验台检查，验证后记录结果。

## 公开行为

- 关闭：`PUT /api/sessions/:id/config`，请求体 `{ "autoCompaction": false }`；开启传 true。
- 未设置的会话默认开启；未传该字段时保持原值；设置只属于当前会话。
- 关闭不影响手动压缩；开启本身不立即发起压缩，后续由 Pi 判断触发时机。
- 非布尔值、空请求或未知字段：400 `INVALID_REQUEST`。
- 未知会话：404 `SESSION_NOT_FOUND`。
- 忙碌：409 `SESSION_BUSY`，停止或完成后可重试。
- 混合请求的模型/档位/凭据校验失败时不先改变开关。

## 接口试验台实际操作

使用 Playwright 打开本地独立试验台，通过页面的请求编辑器、参数示例和发送按钮实际调用后端，没有模拟 HTTP 响应：

1. 创建会话（201），读取配置，确认默认 true。
2. 选择“关闭自动压缩”示例发送（200），上下文查询同步显示 false。
3. 字符串 `"false"` 返回 400；未知会话返回 404。
4. 发起等待中的生成，修改开关返回 409。
5. 从试验台停止生成，再选择“开启自动压缩”示例（200），上下文同步恢复 true。
6. 正常响应字段检查全部通过，页面无 JavaScript 运行异常。控制台三条网络错误分别来自主动验证的 400/404/409。

本机验证材料：`output/playwright/auto-compaction-run.js`、`auto-compaction-report.txt`、`auto-compaction-config.png`、`auto-compaction-context.png`。目录已登记配置读写与上下文返回字段，`tests/demo` 验证开关示例、错误说明和字段类型，现有 52 个路由仍全量覆盖。

## 七条规则核对

1. 不过度设计：在现有配置接口增加一个可选字段，复用 Pi 开关与元数据。
2. 前后端解耦：通过公开契约调用；试验台不读取 SDK 或会话文件。
3. 关键注释：说明会话元数据恢复、默认值、忙碌锁与混合请求验证顺序。
4. 需求明确：完成已同意的自动压缩开关；附件类型和引用范围仍待明确。
5. 旧接口处理：本次是现有接口的增量扩展，未替换或删除旧接口，原模型/档位请求仍可使用。
6. 边框规范：未新增或修改前端样式。
7. 组件归属：试验台复用现有目录驱动的参数与响应检查，没有新增页面封装或通用控件。

本阶段后端与试验台验收通过。附件、普通聊天文件引用、权限三档和计划模式尚未实现。
