## 接入结论与原因

1. 使用独立 `ResourceLoader` 提供系统提示和空资源集合。原因：小说 Agent 不应继承工作区 AGENTS、用户技能或默认编码工具。
2. 通过 `customTools` 注册工具，同时在 `tools` 中显式启用 `read_fixture`。原因：仅注册不代表已启用，传空工具集合也会关闭自定义工具。
3. 直接复用 `SessionManager` JSONL。原因：普通“生成候选 → 用户选择”是多轮消息，不需要额外工作流状态；重启后由用户继续。
4. 使用 `prompt()` 完成与 `agent_settled` 判断最终结束。原因：`agent_end` 可能还会进入 SDK 重试；前端协议不能把每个底层结束事件都解释为最终完成。
5. 检查最后 assistant 消息的 `stopReason`。原因：不能仅以 `prompt()` 未抛异常判定成功；错误和中断也要从结果检查。
6. 关闭缓存预热。原因：验证结束后不需要额外模型请求。

没有引入第二份聊天历史、自动步骤恢复、队列、任务库或兼容旧接口。本轮没有替换旧接口；前端边框规则不涉及本次无界面实验。关键接入函数和测试逻辑已添加职责说明。

人工检查：候选符合资料中的二选一目标；继续文本没有揭示父亲去向，许禾先询问林舟在寻找什么，没有预先知道纸条内容。但续写新增“铜钥匙、仓库编号”等资料外情节，说明当前提示中“依据资料”与“创作新情节”的边界仍须在 P3 明确和评测；本轮不宣称创作质量已验收。停止测试仅证明中断行为，未验收被中断回复的内容。

SDK 自定义条目不适用：当前明确采用普通文字选择，没有按钮状态需求。压缩和有限重试仅完成配置核对，未强制触发；百万上下文、所有推理等级、图像输入和超长输出不在本轮验收范围。
