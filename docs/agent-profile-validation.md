# 全局 Agent 人设

2026-11-21。Plotloom 在本机数据目录中保存一份 Agent 人设，由所有项目和小说共用。

## 首次使用与修改

待引导时，项目和小说的普通聊天加入 BOOTSTRAP 提示。用户打招呼或愿意认识 Agent 时，助手用自然语言询问称呼、性格和协作偏好。开场有具体任务时先处理任务。用户可以晚点再设置。助手归纳内容后通过 `setup_agent_profile` 发出聊天内确认卡，用户选择确认后才将配置写入本机的 `agent-profile.json`。用户明确要求永久跳过时，工具也会请求确认。停止、自填或跳过当前确认卡都不会提交该操作。

配置或永久跳过后，应用刷新和重启都会保留状态。可在「设置 → Agent 人设」手动编辑，空字段使用默认行为。结构化小说工作台通过专用创作接口执行当前任务，普通小说聊天可完成首用引导。

设置由服务端加入现有项目、小说及结构化创作的系统提示。每轮开始时固定人设。保存从下一轮新请求生效，已开始的轮次及其重试使用原快照。新增人设只影响 Agent 的介绍、表达及协作方式，现有职责、工具权限和正文采纳规则仍由原契约执行。

## 公开接口

| 方法与路径 | 请求与结果 |
| --- | --- |
| `GET /api/agent-profile` | 返回 `setup`、`name`、`style`、`preferences`。首次读取状态为 `pending`，文本字段均为空。 |
| `PUT /api/agent-profile` | `{"action":"save","name":"小舟","style":"简明","preferences":"先核对参考资料"}` 保存整份人设。`{"action":"skip"}` 将待处理引导标为 `skipped`，保留已保存设置。两个操作均返回当前记录。 |

保存会去掉字段首尾空白。三个文本字段上限分别是 40、160、1000。无效或超长字段返回 `400 INVALID_REQUEST`。异源浏览器请求返回 `403 ORIGIN_FORBIDDEN`。两条接口都可以从试验台「Agent 人设」模块调用。

聊天引导复用发送消息的 `user_answer_required` 事件和回答问题接口。确认卡的第一项提交所展示的操作，其他回答只结束当前确认。刷新后可通过会话详情的 `pendingQuestion` 找回确认卡。用户在另一处先完成设置时，旧确认不会覆盖该记录。

## 验证

- 独立 HTTP/SSE 测试检查初始、保存、跳过、刷新所依赖的持久状态、重启、异常参数、异源请求，以及在项目及小说实际提交给模型的系统提示。生成中修改配置时，当前轮和重试继续使用原设置，下一轮读取最新设置。
- 首用回归验证确认前不写盘、继续修改和停止保留待引导、确认写入真实配置文件、重启保留人设，以及引导完成后新的模型请求不再获得首用工具。人设、Agent 提问、配置和小说接口共 27 项通过，试验台自动化 16 项和界面自动化 29 项通过。类型检查、Web 和试验台构建通过。
- Edge 正式页面实测自然语言往返、刷新恢复确认卡、确认落盘及设置回读和手动修改。试验台实测等待确认、停止、确认永久跳过、手动保存、重复跳过和无效请求。浏览器使用确定性模型替身。复现见 [正式页面脚本](../tests/ui/agent-profile-browser.js) 和 [试验台脚本](../tests/ui/agent-profile-demo-browser.js)。
