# 聊天附件与文档引用计划

日期：2026-11-19。

## 用户确认范围

- 普通聊天既能引用已登记小说工作区的指定版本文档，也能引用当前聊天上传的附件。
- 附件支持 PNG、JPEG、WebP，以及 UTF-8 TXT、Markdown；不支持 PDF/Word。
- 本阶段补公开后端能力与接口试验台；不重做产品聊天 UI、权限预设或计划模式。

## 实现顺序与决定

1. 公开契约：增加附件上传、列表、读取、移除；消息请求增加 attachmentIds 和 references，允许纯附件或纯引用消息。老文本/技能请求继续使用。
2. 分层实现：application 负责文件校验、归属与上下文编译，storage 保存不可变附件，agent-pi 仅负责 Pi 图片输入及消息历史投影；前端只消费公开协议。
3. 附件用 JSON base64 上传和读取，沿用试验台现有 JSON 请求机制；文件选择器负责编码，业务接口不接收本机路径。图片单个 10 MiB，文本 1 MiB，单轮最多 10 个附件、合计 20 MiB；文本与文档上下文合计不超过 100000 字符。
4. 文档引用传 workspaceId、相对 path、内容 version，可带 UTF-16 选区；复用工作区版本快照，按指定版本读取，不用最新稿静默替换。普通聊天可显式引用已登记工作区；已有小说聊天仍仅允许本书资料，不借此放开跨书工具权限。
5. 保存原始用户文字、附件元信息、引用内容快照，用于重启和历史回显；模型上下文使用实际文本和图片，页面不显示内部拼接提示。
6. 移除只删除尚未被消息引用的附件，已发送附件保留历史并返回 ATTACHMENT_IN_USE；与发送共用会话互斥锁，避免读删竞争。新上传文件不影响正在生成的请求。
7. 目录与试验台：登记所有新路由、字段、限额、错误和消息结束状态；提供实际文件选择/读取预览、自动沿用附件 ID；同步 tests/api 与 tests/demo。
8. 验证：上传和类型/编码/大小错误，附件跨会话隔离，图片模型不支持，纯附件/引用，版本和选区，资源重建及重启，发送与删除并发，SSE 停止及失败，试验台实际操作；记录七条规则核对。
