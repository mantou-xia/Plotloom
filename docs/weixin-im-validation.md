### 专项场景

- 本人扫码、PIN 前导零、协议鉴权头、凭据不进入公开响应、禁止异源请求。
- 没有入站上下文时仍能发起主动消息；相同业务键重复请求不重发，不同文字冲突；UTF-8 字节上限。
- uint64 消息 ID 无精度损失，重复回放只调用一次 Agent；其他用户、其他 bot 和群消息不进入会话。
- 最终回复来自本轮 Agent，微信回复携带最新上下文；不支持的媒体明确失败。
- 服务端拒绝、断网、无效响应和 503 分别记录 rejected/unknown；同键再次调用不尝试发送。
- 并发同键仅一次微信请求；重启恢复游标、上下文和发送结果；进程强退后不重放生成和发送。
- 通过微信回答真实 Agent 选择题、明确批准文件写入；未审批前文件不存在，批准后写入正确。
- 忙时反馈、微信停止、停用取消生成；两个微信账号独立会话；冲突绑定拒绝。
- 登录失效后停止接收、重新扫码恢复；非微信服务地址拒绝；删除通道保留 Agent 会话。

协议替身以真实 HTTP 服务模拟微信；模型使用已有确定性协议 fixture。业务、文件存储、Pi SDK、工具审批与公开 HTTP 路由均为生产实现，不以 mock application 代替核心链路。

## 真人验证

1. 用户本人扫码并授权，试验台返回 `confirmed`，服务开始接收手机消息。
2. 首次对话因隔离服务使用旧模型凭据而返回 401。同步主应用保存的模型配置后，独立会话生成通过，用户随后确认手机收到了正常的 Agent 回复。
3. 待验证平台在没有新入站消息时主动发送通知，并由用户确认手机收到。长时间无交互后的发送窗口也待实测。

## 2026-11-26 微信普通聊天与人设

全局扫码后，第一条普通文字直接进入无工作区对话；从小说或项目发送「回到普通聊天」会恢复原来的历史。普通对话通过持久标记跨重启保留，启动仍清理未标记的旧无归属会话。普通对话不注册项目文件工具。

微信生成轮次复用平台人设，补充适合微信的表达规则；重试沿用原轮的通道和人设。切换、审批与失败等固定提示使用人设名称。微信和模型协议替身验证了首条普通聊天、跨目标隔离、重启后恢复、提示词及人设即时更新。接口试验台、项目与人设回归合计 33 项通过，类型检查和差异检查通过。真人微信上的语气效果待实测。

## 2026-11-26 微信分轮授权

微信通用文件工具每轮暂存一项变更，等模型轮次释放会话后才发预览。下一条微信消息可直接批准或拒绝，批准绑定当前微信连接和会话，重新核对路径及文件快照后写入，并把审计与文件差异记到原请求轮次。待确认计划仅在当前连接有效，停用、改绑或服务重启后需重新请求。小说等专项业务确认仍在网页发起。

类型检查和 24 项微信、项目、实时审批及试验台回归通过。协议替身验证预览发出时会话已空闲、确认前文件不存在、单独发送「批准」后才写入、重复批准不可复用、拒绝不写入、外部修改不被覆盖，以及写入差异归属。网页实时审批继续通过项目回归。本次未改产品组件或新增公开路由，更新了微信收发记录的接口试验台说明。真人微信待复测。
