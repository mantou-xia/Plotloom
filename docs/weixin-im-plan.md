# 微信 IM 通用接入计划

日期：2026-11-24。工作分支：`codex/weixin-im`，从 `main@6873b0e` 创建独立 worktree。

## 目标与边界

- 通过腾讯公开的 iLink 协议扫码绑定本人微信，收取文字并交给已有 Plotloom 会话，返回最终答复。
- 通道绑定已有项目或小说会话，沿用模型、人设、技能、提问和文件审批；原因是现有 Agent 明确要求会话具有项目或小说归属，不另建不受约束的 Agent。
- 提供通用主动发送接口，调用方显式提交文字和幂等键。向扫码绑定的本人发送，保存服务端接受、拒绝或结果不明；不声称具有已读或终端送达回执。
- 实现微信内停止、回答问题、明确批准/拒绝待审批调用，避免 Agent 在微信入口不可操作地挂起。
- 本阶段不扩展记账、定时调度或媒体处理。图片等不支持的消息明确反馈，避免静默当作成功。

## 实施顺序与原因

1. 定义公开通道、登录状态和消息结果契约；在 application 定义业务与端口，storage 保存私有凭据和状态，server 实现微信 HTTP 适配。前端只使用公开接口。
2. 支持扫码、PIN、官方重定向、连接启停与重新绑定。限制凭据发送主机；错误不回传原始微信响应，避免泄露 token。
3. 长轮询先持久化收到的消息和游标，再分发。按微信消息 ID 去重；重启将未完成执行标为中断，不自动重放可能已产生业务副作用的请求。
4. 主动发送先保存 sending，再调用微信；同一幂等键不二次发送。断网、超时和进程中断标为 unknown，由调用方检查，不擅自重发。
5. 全部公开接口登记到 catalog，复用接口试验台现有参数编辑与结果检查，补充登录 ID/账号 ID 自动带入。
6. 真实 HTTP 协议替身覆盖扫码/PIN、收发、去重、会话隔离、主动触达、上游失败、重启与停止；同步 tests/demo 覆盖，构建和逐条核对十条规则。
7. 微信真人扫码与手机收发为最终外部验收，需要用户本人完成扫码。协议替身通过与真人通过分别记录，未完成真人步骤不得声称已验证实际触达。

## 协议依据

- Tencent/openclaw-weixin：`docs/protocol_zh_CN.md`、`src/api/types.ts`、`src/api/api.ts`，2026-11-24 核查。
- 当前参考版本 `3.0.0-beta-1`；`base_info.channel_version` 保持兼容前缀，`bot_agent` 标识 Plotloom。
- 主动发消息仍受微信服务端约束；优先携带最近入站 context_token，缺少上下文也记录实际发送结果，不能承诺任意时段一定可达。
