# P7 小说工作台闭环验收

日期为 2026-11-21。正式 Web 入口为侧栏「小说管理」。

## 交付与依据

- 作者可登记本机小说文件夹，打开或新建 Markdown 文稿，手工保存正文、人物资料及正式大纲。当前路径和未保存草稿以小说和文稿为单位在当前浏览器恢复。草稿附原版本，发现外部改稿时可复制草稿核对，禁止用旧版本覆盖。
- 创作复用小说会话、P3 任务和 P1 SSE/停止协议。工作台支持按正式大纲写章节、续写、精确选区改写与丰富大纲。发送时读取所选参考资料的实际版本，创作记录展示本轮使用的原文与审校证据。
- 候选由后端持久化，使用现有文件差异组件展示。作者对每处独立采纳或拒绝，历史恢复、正式稿下载及版本冲突继续走 P2 契约。界面使用现有布局和控件，通过固定位置的状态区及浮动提示反馈。
- 本轮沿用已登记和验收的公开接口。资产、生成、会话和候选仍分别由后端负责，产品前端仅发起 HTTP/SSE 请求。参见 [P2](p2-validation.md)、[P3](p3-validation.md) 和 [接口试验台](api/demo.md)。

## 验证

- 在 Edge 正式产品页连接真实本机服务，模型使用确定性协议替身，执行 [小说工作台浏览器回归](../tests/ui/novels-browser.js)。覆盖登记、正式大纲原样保存、草稿和候选刷新恢复、章节生成、CRLF 加 emoji 的重复句选区、实际引用版本、同一候选逐处采纳与拒绝、过期候选拒写、冲突草稿保留、恢复、下载和刷新后停止。比较了生成前与生成中按钮的位置和宽度。
- 类型检查、Web 构建、15 项试验台测试、29 项界面自动化和正式页面路由回归通过。路由回归覆盖小说管理刷新、浏览器前进后退、设置返回以及原有聊天和项目地址。
- 全量接口回归串行执行通过 94 项。并行执行时，基础 Agent 的浏览器来源用例在关闭并重启 Fastify 后触发 `AVV_ERR_READY_TIMEOUT`，随后同组请求连接被拒绝。基础 Agent 单独运行通过 10 项。串行复现命令为 `node --test --test-concurrency=1 tests/api/*.test.ts`。
- 在独立 P2/P3 HTTP 回归中核对磁盘外部修改、引用变化、停止、断流和重启，确认未采纳的修改不写入正式稿。模型质量参考 [P3 真实模型样本](p3-validation.md)，本轮浏览器验收使用协议替身，作者连续写作体验待实测。

## Agent 能力审查

- 当前闭环已具备小说归属、技能与资料装配、流式生成、停止及已完成结果恢复。正文保护由版本校验、受限候选工具和作者逐处采纳实现。可以直接使用这套能力迭代创作产品。
- 创作会话的重试入口可重放结构化请求，按目标和引用原版本重新执行，并生成独立候选。新创作轮次保存原模型、思考档位、自动压缩设置及有效技能版本。旧轮次从已保存的创作上下文恢复请求，缺少配置快照时使用当前会话设置。详见 [P3 创作接口](api/p3-writing.md)。
- P8 仍应验收有副作用工具的权限与执行隔离、写入结果不确定时的核对和整应用备份恢复。长篇记忆、自动检索及高级审校按 P4—P6 排期，根据连续写作样本确定优先级。

## 结构化创作重试复验

- Edge 接口试验台实测保存正文、指定重复句中的第二处改写、重试并查询新候选、停止重试，以及目标改稿后收到 `409 REVISION_CONFLICT`。同次浏览器回归覆盖通用重试、旧消息 ID 拒绝、原会话停止和正文来源。
- 类型检查、试验台构建和 16 项试验台测试通过。目录直接复用原 `generation.retry` 路由，登记结构化重试示例和版本错误。
- 小说 HTTP/SSE 回归 12 项通过，覆盖原选区、参考片段、大纲、预算、模型与思考档位、禁用技能、文件版本冲突和旧记录恢复。另验证临时重试设置在强制退出后也不会覆盖会话设置。
- 本次全量串行回归出现基础 Agent 的 Fastify 重启超时及连带连接失败，以及供应商测试临时目录清理的 `ENOTEMPTY`。两组单独复跑分别通过 10 项和 2 项。
