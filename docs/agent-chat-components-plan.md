# Agent 对话页面组件实施计划

日期：2026-11-19。

状态：C01 MarkdownRenderer 与 C02 CodeBlock 已完成组件及调试台验收；C02 已补齐独立导出、样式和八个调试样例。C03～C06 已完成统一过程组件与调试台验收：C04 简化为 ThinkingContent，C05 按发生顺序组织全部可见过程，C06 展示工具详情，C03 插槽组合整个过程区域。C07 UserMessageBubble 已完成原文气泡、附件插槽与七个调试样例验收。其他进度见下表；聊天页面接入与 A2UI 尚未实施。

## 目标与范围

为具体 Agent 对话页面建立消息内容、执行过程、附件引用和消息操作能力。优先复用现有组件；通用能力与具体页面组合保持分离。

用户提供的三张参考图分别用于说明执行步骤及工具调用、文件附件卡片、图片附件横向展示。图片中的命令和文件名仅是界面示例，不是需要执行的任务。

组件名称暂定。下面的功能项不等同于必须分别建立公共组件；具体归属在开发该项前按实际复用情况确认。

## 现有能力与边界

- 已有 `TaskComposer` 输入组件，以及按钮、弹层、提示、滚动容器等基础能力，优先复用。
- 当前聊天页面已有简易正文、思考内容、工具结果和附件展示，需要逐项完善。若准备替换旧实现，须先按项目规则询问用户是否仍需保留或兼容；本计划不代表已授权清理旧实现。
- 当前上传入口开放 PNG、JPEG、WebP、TXT、Markdown。文件卡片展示 Word、Excel、PDF 等类型，不代表后端已支持上传、解析或处理这些文件；扩展处理能力须单独确认。
- C05 按实际发生顺序穿插展示思考、过程说明、工具、步骤、重试、上下文整理、失败与停止等记录，最终回答位于过程区域外。只展示公开接口实际提供的内容，不补造过程或耗时。2026-11-20 用户已明确批准移除旧 ThinkingPanel，无需兼容。
- 引用和重新生成接入真实业务前，需核对公开接口能力与操作语义。

## 开发与验收约束

- 每项编码前先做好计划，并检查现有组件库。只实现当前明确需求，不提前建立扩展框架。
- 通用规范或实际复用成立的能力放入 `packages/ui`，样式随组件维护；具体业务组合放入 `apps/web`。
- 组件通过 props、children 和回调接收数据与操作，不直接请求后端，不依赖应用内部状态、Pi SDK、数据库或本机文件。
- 新增公共组件同步提供组件调试台示例和公开参数控制，不用完整业务页面代替组件示例。
- 关键函数和重要业务逻辑注明职责、规则和处理原因。
- 层级优先通过背景和间距表达；禁止完整边框套嵌、边框加阴影制造深度、彩色 / 虚线 / 渐变边框及 outline 与 border 叠加。聚焦态遵循项目规范。
- 图标使用项目统一图标库，不使用字符或 emoji 代替界面图标。
- 按本项实际行为完成必要检查，包括适用的流式更新、折叠、复制、滚动、窄屏、键盘操作和状态反馈，记录真实结果；未完成验收不标记完成。
- 涉及公开业务接口新增或修改时，同步更新 `packages/contracts/src/catalog.ts`、`apps/api-demo` 展示、`tests/api` 独立接口测试与 `tests/demo` 覆盖测试；完成试验台实际触发及正常、错误、停止等适用流程验证，记录阶段验收结果。
- 每次交付逐条核对根 `AGENTS.md` 八条规则；本文件不替代项目规则。
