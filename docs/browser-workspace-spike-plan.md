# 浏览器工作区技术验证计划

2026-11-20，用户批准先验证完整链路，再决定工作区框架。

## 已确认需求

- 文件仅 Markdown、图片，只读预览。
- 浏览器需要完整网页交互并能由现有 Agent 操作；必要时仅 Electron 提供。
- 用户与 Agent 操作同一个可见浏览器会话，切换预览后返回保留登录和页面状态。
- 原 SplitPaneLayout 只是布局，不能作为上述能力的完成标志。本轮不删除或替换现有布局、接口，不迁移至 Theia。

## 实施顺序

1. 独立目录 `experiments/browser-workspace`：固定 Electron、Playwright 版本，不改变产品入口。
2. Electron WebContentsView 承载真实网页，独立 session 隔离壳与网页；测试站点使用合成账号与内容，不操作用户真实账户。
3. 外部 Node 验证进程通过 CDP 定位同一个 WebContentsView；操作接口仅用于实验，不作为公开业务接口交付。
4. 验证登录、前进后退、刷新、输入、点击、滚动、页面截图、文件预览切换、手动操作接管，以及错误/中止后的可恢复状态。
5. 通过现有 AgentService 的工具注册入口执行真实模型任务。记录 target 身份、工具事件、页面结果；不记录凭据。
6. 输出可运行实验、截图与验收结论，区分验证通过、限制和尚未建设的产品能力。

## 关键决策

- 只使用当前明确需要的浏览器与预览能力，先不引入完整 IDE。
- 浏览器控制留在宿主/后端；渲染层只发送明确操作，不暴露 Node 或任意系统执行。
- CDP 仅绑定本机临时端口、实验结束关闭进程；正式产品需要独立设计控制桥、权限及公开契约。
- 复用成熟 Playwright 操作和现有 Pi 工具循环，先检验 WebContentsView/CDP 同会话兼容性。
