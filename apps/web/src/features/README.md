# Feature 组织约定

正式产品前端按业务 feature 组织，不按所有页面、所有 hooks 等技术类型集中堆放。

每个实际功能在这里建立独立目录，目录内按需维护页面装配、状态、hooks 和公开 HTTP / SSE 接口调用。当前 `settings` 管理主题偏好及浏览器持久保存；`agent` 管理普通/项目会话创建、TaskComposer 适配、流式事件、运行快照和附件历史预览；`skills` 展示已安装技能列表。品牌、导航和最近会话由应用层组合，通用侧边栏与布局复用 `packages/ui`；小说入口仅占位，不接小说业务。

`agent/chat-composer.tsx` 并行读取会话配置、模型能力、上下文、技能和工具；配置先保存，发送在服务端接收后清空草稿。项目目录只提交给公开接口校验，前端不读磁盘；@ 项目引用发送相对路径文字，由 Agent 工具读取。项目创建后目录固定，普通聊天不会自动获得文件修改与终端能力。

- 页面优先组合 `@plotloom/ui` 通用组件；页面专有内容、一次性业务展示和样式在应用或 feature 就近维护。
- 通用框架标准、基础控件及实际多处复用的卡片/功能组件统一维护在 `packages/ui`。不把整页包装成库组件，不在 feature 另建通用组件库或复制已有组件。
- feature 不直接引用另一个 feature 的内部文件；跨功能组合由 `src/app` 负责。
- 只通过公开协议访问后端；实际接入接口时按需引用 `@plotloom/contracts`，不得引用服务端内部包、Pi SDK、数据库或本机文件。
- 路由、状态管理和编辑器等依赖等到具体页面需要时再引入。
