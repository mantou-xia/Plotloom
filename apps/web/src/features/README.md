# Feature 组织约定

正式产品前端按业务 feature 组织，不按所有页面、所有 hooks 等技术类型集中堆放。

每个实际功能在这里建立独立目录，目录内按需维护页面装配、状态、hooks 和公开 HTTP / SSE 接口调用。当前 `settings` 管理主题偏好及浏览器持久保存，页面使用 `packages/ui` 的通用 ColorSwatches，品牌、导航与保存反馈在应用内组合；不预建书架、编辑器、助手等业务模块。

- 页面优先组合 `@plotloom/ui` 通用组件；页面专有内容、一次性业务展示和样式在应用或 feature 就近维护。
- 通用框架标准、基础控件及实际多处复用的卡片/功能组件统一维护在 `packages/ui`。不把整页包装成库组件，不在 feature 另建通用组件库或复制已有组件。
- feature 不直接引用另一个 feature 的内部文件；跨功能组合由 `src/app` 负责。
- 只通过公开协议访问后端；实际接入接口时按需引用 `@plotloom/contracts`，不得引用服务端内部包、Pi SDK、数据库或本机文件。
- 路由、状态管理和编辑器等依赖等到具体页面需要时再引入。
